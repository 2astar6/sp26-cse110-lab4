1. A developer may not like JavaScript's asynchronous nature because it forces lower performance and is less deterministic than fully synchronous code - causing race-conditions, incorrect UI update steps, and much more. They may also dislike its loose typing because type conflicts are not clear and may require more thinking and debugging if a mistake is made. They may also find the web platform it runs on a pain to deal with due to varying behavior of platform/browser types, reliance on rapidly-changing APIs to access browser features, and the need to support older browser versions.  
2. Those who created JavaScript likely opted for loose typing to make the language easier to adopt by more people, similar to Python's approach. They likely also opted for async work to allow slower common events like network requests to not block the single-thread architecture that was chosen for browsers. 
3. A compiled language is formatted into binary/machine-code that a computer can understand before it is ran while an interpreted language is ran line by line at runtime as it is processed by the interpreter. JavaScript is a combination of both. While it mainly runs as an interpreted language, frequently used code is automatically compiled beforehand for increased speeds. This helps improve performance while still allowing for the loose typing to be supported, since types are not guaranteed at runtime.  
4. Practicing plain JavaScript is essential for building good fundamentals and understanding the unique mechanisms of the language, which underlies much more complex web frameworks. In the ever-changing web development landscape, it is imperative to understand the core mechanisms and reasoning behind them since those rarely have a revolution.
